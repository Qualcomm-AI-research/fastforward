    yaqa

    YAQA: weight rounding against a Kronecker-factored Hessian of the model-level loss.

    Introduced in https://arxiv.org/abs/2505.22988. GPTQ rounds a layer against the Hessian of the layer output, E[x x^T]. YAQA rounds it against the Hessian of the model-level loss, which also needs the gradient g of the loss with respect to the layer output. For a weight W of shape (m, n) the Hessian is approximated as H_out (x) H_in, with one factor per side of W.

    The factors are estimated with Sketch B of the paper: one round of power iteration, started from the identity, on the per-sequence weight gradient G = sum_t g_t^T x_t. It needs one pass over the data. Sketch A of the paper treats tokens as independent and needs several passes. It is not implemented. There is no incoherence processing either.

    The factors are the result of a FlowOp that runs calculate_kronecker_factors. It computes the sums behind the factors on one chunk of the calibration data, and combine_kronecker_factors joins the sums of the chunks, so the data need not fit in memory. finalize_kronecker_factors turns the sums into the factors.

    fastforward.algorithms.yaqa.calculate_kronecker_factors(inputs, gradients, *, compute_dtype=torch.float32, accumulate_dtype=torch.float32) #

    Return the sums behind the Kronecker factors of a linear layer for its weight gradients.

    This is the function of the FlowOp that YAQA registers. Sketch B is one round of power iteration on the Hessian, started from the identity. It uses the weight gradient of each whole sequence. It does not treat the tokens of a sequence as independent, as Sketch A does.

    For every sequence s the weight gradient is G_s = sum_t g_{s,t}^T x_{s,t}, with shape (m, n). The factors are H_in = sum_s G_s^T G_s / (N m) and H_out = sum_s G_s G_s^T / (N n), with N the number of sequences. This function returns the two sums and N, and finalize_kronecker_factors does the division. So a chunked run can call the function once for each chunk and join the results with combine_kronecker_factors. For the factors to be correct, gradients must be the gradient of a loss that is a sum over sequences. Then every sequence contributes its own weight gradient.

    The weight gradient and its products are computed in compute_dtype, and added up in accumulate_dtype, on the device of the activations. TF32 matmuls are left to the caller's global setting. A recipe sets the dtypes with functools.partial.

    fastforward.algorithms.yaqa.sampled_nll(logits, dtype=torch.float32) #

    Yield the negative log-likelihood of labels sampled from the model, one scalar per batch.

    This is the default objective of yaqa. A label is sampled for every token from the softmax of the logits, so the gradients of the loss estimate the Fisher information of the model and not the Hessian of a loss on labeled data. The loss is a sum over tokens, not a mean, so every sequence keeps its own gradient scale.

    The loss is computed on the device of the logits, and the labels are sampled with the global random number generator of torch. A model that returns an object, like a Hugging Face model, needs a select on the ModelOutputs that reads the logits tensor from the object. It can also move the logits to the device where the loss is to be computed.

    fastforward.algorithms.yaqa.unit_upper_ldl(hessian, perc_damp, max_perc_damp, *, name='matrix') #

    Factor a damped symmetric positive definite matrix as L D L^T with L unit upper.

    The matrix is damped as H + damp * mean(diag(H)) * I. The factorization starts at damp = perc_damp. If it fails, damp grows by a factor of _DAMP_GROWTH (capped at max_perc_damp) and the original matrix is damped and factored again. Only L is returned, because only L is needed for rounding.

    fastforward.algorithms.yaqa.yaqa(module, factors, perc_damp=0.1, max_perc_damp=1.0, layer_name='') #

    Quantize a QuantizedLinear layer in-place using YAQA.

    The quantization ranges are set once on the original weight and stay fixed. The weight is then rounded onto this grid against the Kronecker-factored Hessian of the model-level loss. The Hessian is estimated with Sketch B, see calculate_kronecker_factors.

    Parameters:

    Name Type Description Default
    module QuantizedLinear

    A QuantizedLinear layer whose weight_quantizer is a LinearQuantizer.

    		 required
    factors tuple[Tensor, Tensor]

    The factors (H_out, H_in) of the layer, of shapes (m, m) and (n, n). finalize_kronecker_factors makes them from the result of calculate_kronecker_factors. They are factored in their own dtype, and the rounding runs in float32.

    		 required
    perc_damp float

    First dampening factor to try, as fraction of the mean diagonal value, for each factor. If the Cholesky factorization of a factor fails, the dampening of that factor grows tenfold until it succeeds or reaches max_perc_damp. The default gave the lowest perplexity of 0.01, 0.1 and 1.0 for W4 Llama-3.2-1B. The value of the paper (1e-4) assumes incoherence processing, which is not part of this implementation. Without it, the small value gives large feedback terms that move the weights outside the quantization grid.

    		 0.1
    max_perc_damp float

    Largest dampening factor to try.

    		 1.0
    layer_name str

    Optional name for logging and error messages.

    		 ''

    Raises:

    Type Description
    ValueError

    If the weight quantizer is not a LinearQuantizer, if the shapes of the factors do not match the weight, or if a factor has non-finite entries or is not positive definite at max_perc_damp.
