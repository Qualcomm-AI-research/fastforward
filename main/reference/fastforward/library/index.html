    fastforward.library.conditional_compile_fullgraph(func) #

    Compile this operator with fullgraph=True if compiled_quant_funcs is enabled.

    torch.compile(func) (used by conditional_compile) allows Dynamo to fall back to eager on parts of func it cannot trace, leaving some of that region's dispatch overhead in place. fullgraph=True instead requires the whole function to trace, which is what lets the Triton kernels this is used for fuse with whatever their caller does with the result — the reference broadcast ops do not consistently support fullgraph=True (their fake implementations are not always called the way it requires), so they keep using conditional_compile instead.

    [source]

    fastforward.library.custom_quant_op(name, *, conditional_compile=True, fullgraph=False) #

    Wraps a function into a custom fastforward and a custom torch operator.

    The function is registered both as
    • A fastforward op at fastforward.ops.<name>.
    • A torch op at fastforward::<name> (torch.ops.fastforward.<name>) (see torch.library.custom_op), which torch.compile treats as an opaque graph node.

    Calling the fastforward op will fire the opaque torch op (in Export mode) or the (maybe-compiled) plain python function (in Compile and Eager mode).

    Library code should always call the returned callable or the fastforward.ops.<name>, and never torch.ops.fastforward.<name> directly, which is always opaque.

    The callable (and the fastforward op) dispatches at call time:

    • When exporting (export_mode enabled or torch.export tracing), the registered torch.ops.fastforward.<op> runs, so it appears as an opaque node in the exported graph, never tracing into the python implementation, and using the registered fake-impl for shapes and dtypes. In this case quant-ops are opaque kernels that cannot be fused with neighbour ops: AOTAutograd and Inductor treat the node as an extern kernel call. The quant-op can still be compiled if conditional_compile=True and when the compiled_quant_funcs flag is enabled (like in eager mode).

    • Under torch.compile, the plain python function runs so its ops stay visible to the compiler (and can be fused with neighbour ops by Inductor), reducing memory movement and obtaining great performances in most cases.

    • Otherwise, the (possibly-compiled) plain python quantization function is run in eager mode. When conditional_compile=True and compiled_quant_funcs flag is enabled, the called function will be the torch-compiled version.

    The ops are not differentiable when called directly: the plain paths run under torch.no_grad(), so their outputs do not require grad. Gradients are provided by the torch.autograd.Function classes that wrap them.

    In eager mode, if an active torch profiler is detected, the call is recorded as a fastforward::<name> range in torch.profiler.

    Parameters:

    Name Type Description Default
    name str

    Name of the operator, without the fastforward:: namespace. Must be a valid ASCII identifier.

    		 required
    conditional_compile bool

    If True, the plain function and the registered op are compiled when compiled_quant_funcs is enabled. If False, they are never compiled.

    		 True
    fullgraph bool

    If True, compile with fullgraph=True. Requires conditional_compile=True.

    		 False

    Raises:

    Type Description
    ValueError

    If the name is invalid, the signature of the function cannot be converted to a torch schema, or an op with the same name is already registered. A rejected op leaves all registered ops untouched. To replace an op, first remove it with deregister_quant_op.

    fastforward.library.deregister_quant_op(name, *, missing_ok=False) #

    Remove an op registered with custom_quant_op.

    Removes fastforward.ops.<name>, the torch op torch.ops.fastforward.<name> and the fake impl registered for it with register_quant_fake. To replace an op, deregister it and register the new op (and its fake impl) afterwards.

    The callable returned by custom_quant_op for the removed op must not be used anymore.

    Parameters:

    Name Type Description Default
    name str

    Name of the op, as passed to custom_quant_op.

    		 required
    missing_ok bool

    If True, do nothing when no op is registered under name instead of raising.

    		 False

    Raises:

    Type Description
    ValueError

    If no op with this name is registered and missing_ok is False.

    fastforward.library.register_quant_fake(name) #

    Register a FakeTensor implementation ("fake impl") for this operator.

    Also sometimes known as a "meta kernel", "abstract impl".

    The op must already be registered with custom_quant_op. The fake impl is removed together with the op by deregister_quant_op.

    See torch.library.register_fake documentation.

    [source]

    fastforward.library.triton_quant_op(name) #

    Wraps a function backed by Triton kernel(s) into a custom operator.

    Unlike custom_op, the operator's implementation stays visible to torch.compile/torch.export, so calls to it can be fused with surrounding operations instead of being treated as an opaque boundary. Any Triton kernel invoked inside the wrapped function must itself be wrapped with wrap_triton for this visibility to apply.

    See torch.library.triton_op documentation.
